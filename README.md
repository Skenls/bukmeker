# GoldBet

Telegram-бот на aiogram 3 для ставок на вымышленную «голду» в личных сообщениях. Реальных денег нет: бот ведёт учёт баланса, событий, ставок и статистики в SQLite.

## Возможности

- Предложение событий игроками и модерация заявок администратором.
- Ставки с коэффициентом от 1.01 до 100 и выплата с округлением вниз.
- Прямые переводы голды между игроками по @username или Telegram ID с защитой от инъекций.
- Отмена события с возвратом ставок и расчёт исхода «выиграл/проиграл».
- Статистика игрока: число ставок, выигрыши, оборот и чистый результат.
- Админ-панель: очередь заявок, открытые события, расчёт исходов.
- Уведомления игрокам о результате ставок и входящих переводах.
- HTML-экранирование пользовательских данных, параметризованный SQL и атомарные транзакции.

## Быстрый старт (Docker)

1. Создайте `.env` на основе `.env.example` и заполните `BOT_TOKEN`, `ADMIN_IDS` (или `ADMIN_CLAIM_CODE`).
2. Запустите:

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

Данные сохраняются в именованном томе `bot_data` и не удаляются при `down` (удалить вместе с данными: `docker compose down -v`).

## Настройка администратора

**Способ 1 — `ADMIN_IDS`.** Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot) и укажите его в `.env`:

```env
ADMIN_IDS=123456789
```

Несколько администраторов — через запятую.

**Способ 2 — одноразовый `/claim`.** Задайте в `.env` длинный случайный `ADMIN_CLAIM_CODE` и отправьте боту:

```text
/claim <ADMIN_CLAIM_CODE>
```

Первый успешный вызов добавляет отправителя в администраторы, повторный уже не сработает. После настройки код можно удалить из `.env`.

Администратор должен хотя бы раз отправить боту `/start`, чтобы бот создал его профиль и показал меню. Панель — `/admin` или кнопка в меню.

## Как работают ставки

- Событие одностороннее: игрок ставит на то, что событие произойдёт. Коэффициент задаёт автор заявки.
- Одна ставка на одно событие от одного игрока.
- Автор события и администраторы не могут делать ставки.
- Выигрыш = `ставка × коэффициент`, дробная часть отбрасывается (округление вниз).
- При исходе «не произошло» ставка сгорает.
- При отмене события ставка возвращается полностью.
- Заявки на модерации ограничены (`MAX_PENDING`, по умолчанию 3).
- Минимальная ставка задаётся `MIN_BET` (по умолчанию 10), стартовый баланс — `START_BALANCE` (по умолчанию 50 000).

## Перевод голды

- Перевод доступен из главного меню по кнопке «💸 Перевод».
- Получатель указывается через `@username` или числовой Telegram ID.
- Получатель должен быть зарегистрирован в боте (хотя бы раз запустить `/start`).
- Перевод самому себе заблокирован.
- Сумма перевода строго валидируется (целое положительное число не превышающее баланс).
- Все операции проводятся в атомарной транзакции SQLite с блокировкой `BEGIN IMMEDIATE` (защита от двойного списания).
- Получатель получает мгновенное уведомление в ЛС о входящем переводе.

## Безопасность

- SQL-запросы параметризованы; данные пользователей не подставляются в текст запроса.
- Пользовательские строки экранируются для HTML перед отправкой в Telegram.
- Начисление, списание и расчёт выполняются в атомарных транзакциях SQLite с блокировкой.
- Callback-данные проверяются по фильтрам и правам; чужие ставки и закрытые события недоступны.
- Bootstrap-код `/claim` сравнивается через `secrets.compare_digest` и действует один раз.
- Контейнер работает от непривилегированного пользователя (uid 10001).

## Данные и резервная копия

База лежит в томе `bot_data` по пути `/data/bot.db`. Для согласованной копии остановите бота и скопируйте файл:

```bash
docker compose stop bot
docker compose cp bot:/data/bot.db ./bot-backup.db
docker compose start bot
```

Храните резервные копии вне хоста с ботом.

## Ограничения

- Используется `MemoryStorage`: незавершённый ввод (например, создание события) теряется при перезапуске.
- Поддерживается только один процесс бота: несколько экземпляров на одной SQLite-базе работать не должны.
- У событий нет дедлайнов и автозакрытия — исход вручную фиксирует администратор.
- `BOT_TOKEN` в `.env` — секрет. Если токен передавался в чате или попадал в переписку, перевыпустите его у [@BotFather](https://t.me/BotFather) командой `/revoke` и обновите `.env`.
